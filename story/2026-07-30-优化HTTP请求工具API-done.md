# 优化 HTTP 请求工具 API

## 背景

`HttpRequestUtils` 已通过统一的底层执行方法提供多种 HTTP 动词便利方法，但当前
API 使用 `Object`、`boolean` 和可变请求头组合表达查询参数、正文类型及请求配置，
存在请求头被误识别为查询参数或正文、请求级配置调用参数冗长等问题。底层实现还
存在链路追踪头重复或无法注入、查询参数拼接不可靠、无正文请求仍被识别为可携带
正文请求，以及响应消费和关闭职责不清晰的问题。

## 目标

- 修复请求构造、追踪头注入、URI 参数拼接和响应关闭问题。
- 补齐高频且语义明确的便利方法。
- 提供类型化请求构建器和自动关闭响应的处理方式。
- 保留现有公开 API，避免破坏已有调用方。

## 范围

- 修改 `HttpRequestUtils` 的内部请求构造与响应消费实现。
- 补充仅携带请求头的 HTTP 动词重载。
- 补充按 HTTP 动词命名的请求级配置方法。
- 新增 `HttpRequestSpec` 类型化请求描述及 Builder。
- 为 `HttpRequestOptions` 增加支持部分覆盖的 Builder。
- 新增响应处理器及常用字符串、JSON响应处理实现。
- 补充与本次修改直接相关的单元测试和 README 使用说明。

## 非目标

- 不升级 Apache HttpClient 或 Jackson 版本。
- 不移除或重命名现有公开方法。
- 不改变连接池生命周期及 TLS 配置策略。
- 不实现异步请求构建器。

## 关键设计

- 所有历史方法和新增便利方法最终复用同一个私有执行流程。
- 使用 Apache `URIBuilder` 合并已有查询参数、新查询参数和 fragment。
- 无正文请求使用普通 `HttpRequestBase`，有正文请求使用
  `HttpEntityEnclosingRequestBase`。
- 调用方显式传入的链路追踪请求头优先；仅在请求头不存在时从 MDC 注入。
- 响应转换方法在成功或异常路径都关闭响应，并使用专用异常表达响应读取失败。
- headers-only 重载解决单个 `Header` 被识别为 `Object` 参数的问题。
- `HttpRequestSpec` 通过互斥的 JSON、表单、文本和 `HttpEntity` 正文方法明确
  正文语义。
- `HttpRequestOptions.Builder` 未设置的字段继承当前 `HttpRequestUtils` 的连接池
  默认配置。
- 响应处理器由 `HttpRequestUtils` 统一管理响应关闭，避免调用方遗漏资源释放。

## 验收标准

- 未显式传入 B3 请求头时能从 MDC 注入，显式请求头不会被覆盖或重复。
- 查询参数可正确追加到已有查询参数和 fragment 之前，空参数不改变 URL。
- 无正文 GET 等请求不会被 Apache 识别为 `HttpEntityEnclosingRequest`。
- 响应读取成功或失败后都能关闭响应。
- 各 HTTP 动词支持 headers-only 调用，并可通过命名方法应用请求级配置。
- `HttpRequestSpec` 支持查询参数、请求头、请求配置及互斥正文类型。
- 响应处理器支持字符串、普通类型、泛型类型和 snake_case JSON 转换。
- 现有测试和新增测试全部通过，项目可正常构建。

## 当前进度

需求已完成。请求工具已修复核心执行问题，补齐便利 API，并新增类型化请求、
部分覆盖配置和自动响应处理能力。新增及现有测试共 22 个全部通过，Maven package
和 Javadoc 检查通过。

## 风险与阻塞

- 新增 headers-only 重载会让源码中故意把 `Header` 实例作为查询参数或 JSON 正文
  的调用改为按请求头处理；该用法不符合原 API 的正常语义，正常请求头调用已经过
  编译和行为测试。
- 无阻塞项。
