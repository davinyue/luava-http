# 修复连接池配置与释放

## 背景

当前同步和异步 HTTP 客户端在默认构造、共享连接管理器、空闲连接清理和响应释放方面存在资源泄漏或行为不一致问题。

## 目标

明确连接池所有权，使客户端关闭时能够可靠释放连接管理器和清理线程，并通过本地测试验证连接可复用、可回收。

## 范围

- 修复 `HttpRequestUtils` 的客户端复用和关闭行为。
- 修复同步连接池清理周期配置。
- 修复异步连接池和清理线程生命周期。
- 阻止当前封装无法安全支持的共享连接管理器模式。
- 补充连接池相关回归测试。

## 非目标

- 不迁移 Apache HttpClient 5。
- 不重构请求参数、链路追踪和 TLS 配置。
- 不改变现有请求方法的返回类型。

## 关键设计

- 构建器内部创建的连接管理器始终由对应客户端持有并关闭。
- `HttpRequestUtils` 始终缓存一个客户端并实现 `AutoCloseable`。
- 同步和异步空闲清理器均使用独立的清理周期，并纳入客户端关闭流程。
- 原始 `CloseableHttpResponse` 继续由调用方负责关闭，通过文档和测试明确约束。

## 验收标准

- 无参 `HttpRequestUtils` 不再为每次请求创建新客户端。
- 同步和异步客户端关闭后，连接管理器及清理线程均停止。
- `connectionManagerShared=true` 在构建时给出明确异常。
- `cleanSleepTime` 在同步和异步模式下均控制清理周期。
- 测试不依赖外部文件或本地服务。

## 当前进度

已完成以下内容：

- `HttpRequestUtils` 复用默认连接池并实现 `AutoCloseable`。
- 同步和异步清理线程统一纳入客户端生命周期。
- 同步客户端使用 `cleanSleepTime` 作为清理周期。
- 共享连接管理器模式改为构建时明确失败。
- 异步IO线程数支持配置。
- 外部依赖测试替换为本地可重复测试。
- Java 8 测试、Java 17 运行测试及 Maven 打包均通过。

## 风险与阻塞

- `connectionManagerShared=true` 现在会构建失败，可能影响依赖原错误行为的调用方。
- 返回原始 `CloseableHttpResponse` 的接口仍要求调用方主动关闭响应。
- Apache HttpAsyncClient 4.1 已停止维护，升级 HttpClient 5 不在本次范围内。
